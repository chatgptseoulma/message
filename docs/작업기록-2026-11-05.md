### 배운 점 / 기억할 점
- 이 폴더는 **하나의 프로젝트가 아니라** 서로 독립된 작은 웹앱 모음입니다. git, 루트 package.json, 테스트가 처음엔 없었습니다.
- **Supabase 프로젝트 공유**: `survey-vercel`과 `comfort-letters`가 같은 Supabase 프로젝트를 씁니다.
  - 그래서 comfort-letters의 migrations 폴더에 설문용 `responses` 마이그레이션이 같이 들어 있습니다.
  - **지우면 안 됩니다.** 마이그레이션 기록이 어긋납니다.
- **설문 결과 공개 설정**: `survey-vercel`은 `RESULTS_PUBLIC = true`라서 결과와 CSV(이름·사번 포함)가 공개 상태입니다.
  - 공개로 바꾼 이 수정이 마지막 배포 기록보다 늦습니다. 그래서 실제 사이트에는 아직 반영되지 않았을 수 있습니다.
  - 다시 `false`로 돌리려면 `vercel.json`의 `/login → /results` 리다이렉트도 함께 지워야 합니다. 그대로 두면 무한 루프가 생깁니다.
- **루트 HTML 4개는 조각 파일**입니다. `<!doctype>`/`<head>` 없이 Claude 미리보기용으로 만들어졌습니다.
  - 배포하려면 `commute-break/index.html`처럼 문서 틀을 씌워야 합니다.
- **같은 내용의 두 파일**: `퇴근길쉼표.html`과 `commute-break/index.html`은 본문이 같습니다. 하나를 고치면 다른 쪽도 고쳐야 합니다.
- **비밀값 취급**: 문서 어디에도 비밀값을 적지 않았습니다. 해당 파일은 `admin_password.txt`, `.env.local`, `pooler-url`입니다.

## 2단계. 리팩토링 전 회귀(특성화) 테스트 작성

### 왜 했나
리팩토링을 하기 전에 **"지금 이렇게 동작한다"는 사실을 테스트로 못 박아 두기** 위해서입니다.
- 지금 코드에서는 모두 통과합니다.
- 리팩토링 후에 하나라도 실패하면, 동작이 바뀌었다는 뜻입니다.
- 이런 테스트를 **특성화 테스트(characterization test)** 라고 부릅니다.

### 어떻게 했나
1. 공용 준비를 먼저 했습니다.
   - `tests/` 폴더를 만들었습니다.
   - `tests/node`에 테스트용 패키지 jsdom과 fake-timers를 설치했습니다.
   - HTML 앱을 불러오는 공용 하네스 `helpers/html-harness.js`를 직접 만들었습니다.
     - 오디오, 캔버스, 음성, 화면 켜짐(WakeLock), 진동 같은 브라우저 기능을 가짜로 대신합니다.
     - 시계도 가짜로 돌려 시간을 마음대로 진행시킬 수 있습니다.
2. **서브 에이전트 4개를 병렬로** 돌려 각자 테스트를 작성하게 했습니다.
3. 전체를 한 번에 돌리는 `tests/run-all.ps1`을 만들고 전부 통과하는지 확인했습니다.

### 테스트 규칙 (중요)
- **테스트를 통과시키려고 앱 코드를 고치지 않습니다.**
  - 리팩토링 후 테스트가 실패하면 리팩토링을 고칩니다.
  - 동작을 일부러 바꾼 경우에만 테스트도 함께 고칩니다.
- **`quirk:` / `test_quirk_*` 테스트**는 알려진 버그를 지금 모습 그대로 고정한 것입니다. 그 버그를 고치면 해당 테스트도 같이 고쳐야 합니다.
- **스냅샷 테스트는 깨지기 쉽습니다.** 데이터나 반올림 방식이 바뀌면 실패합니다.
  - 예: 부동산 취득세 값은 부동소수 오차에 의존합니다. `5억 → 0.06`.

### 테스트하면서 새로 발견한 것
- **comfort-letters 개편**: 작업 중에 다른 세션("DB Inc 홈페이지")이 comfort-letters를 개편했습니다.
  - 1:1 대화방 구조가 "모든 위로자가 보는 방송형 방" 구조로 바뀌었습니다.
  - `api/rooms.js`, `api/room.js`, `lib/rooms.js`가 새로 생겼습니다.
  - 테스트는 새 코드 기준으로 작성됐고, docs와 CLAUDE.md 설명도 맞춰 두었습니다.
- **comfort-letters 계정 삭제 버그**: 계정을 삭제해도, 그 사람이 마지막으로 쓴 글이 다른 사람의 방 목록(`last_body`)에 남습니다.
- **survey Python 입력 처리 특이점**:
  - 숫자 칸에 `true`나 `4.9`를 보내도 통과합니다.
  - 사번 끝의 줄바꿈은 자동으로 잘립니다.
  - 서버가 HTTP/1.0으로 동작합니다.
- **출근 전 점검표**: 남은 항목을 삭제해서 "출발해도 됩니다"가 되면, 연속 완료 기록이 쌓이지 않습니다.
- **콩알이 키우기**: PC가 절전에 들어갔다 깨면 한 번에 몇 시간이 계산됩니다. 그 결과 확정적으로 병에 걸리고, 아기 단계에서 바로 어른이 됩니다.
- **식단표**: 문서에 있던 "밥 추가 + 밥 덜기 동시 발생" 버그는 11,520개 조합을 돌려 봐도 재현되지 않았습니다.
