# 저장소 개요

This folder is not a single codebase. It is a collection of small, independent Korean-language web apps. There is no git repository, no root package.json, and no tests or linter.

**Before you answer a question or start work, read the matching `docs/` file first.** It records the full results of a complete survey of every file: endpoints, schemas, formulas, localStorage keys, line numbers, and known bugs.

# 명령어

- **Regression tests (run before and after a refactor):** `powershell -ExecutionPolicy Bypass -File C:\2026CC\tests\run-all.ps1`. This runs 90 Python tests and 416 Node tests in about 30 seconds.
  - To run a single file: `cd tests\node; node --test --experimental-test-module-mocks <file>.test.js`.
  - Read [tests/README.md](tests/README.md) for the structure and the rules. In particular: never change app code to make a test pass, and `quirk:` tests pin known bugs.

- **survey (Python):** `python survey/server.py` → http://127.0.0.1:8000. You can also use the `survey` preview in `.claude/launch.json`.
  - Uses only the standard library; nothing to install.
  - Running it from another folder fails with Errno 2, so run it from `C:\2026CC` or from inside `survey/`.
- **Vercel apps (`survey-vercel`, `comfort-letters`):**
  - Install with `npm install`. There are no npm scripts and no build step. Node 20+, ESM.
  - Local: `vercel dev`. `.env.local` only contains `VERCEL_OIDC_TOKEN`, so you must set `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` yourself. survey-vercel also needs `ADMIN_PASSWORD`.
  - Deploy: `vercel deploy --prod --yes`. The CLI is at `%APPDATA%\npm\vercel.cmd`.
  - DB: `npx supabase db push --remote --yes`. This needs `$env:SUPABASE_DB_PASSWORD`.
  - Secrets are Vercel production sensitive variables, set with `vercel env add <NAME> production --sensitive --force`.
- **commute-break:** a static site. Deploy with `vercel --prod` from inside the folder.
- **Single-file HTML:** open it directly in a browser. There is nothing to build.

# 큰 그림 / 주의할 점

- **Two Vercel apps share one Supabase project** (ref `fwpxfnbjwkzuglyrmraz`). Because of that, the `comfort-letters` migrations folder also contains survey's `20261105000000_responses.sql`. **Do not delete it.** The migration history has to stay in sync.
- The Vercel API pattern is the same in both apps:
  - `lib/common.js` holds a lazily created Supabase client, `db()`, that uses the service-role key, plus the `send` and validation helpers.
  - `api/*.js` contains the functions.
  - Every table has RLS enabled with no policies, and access is revoked from anon and authenticated. Only the server can reach the data.
- `survey/` and `survey-vercel/` share the same survey questions (`OPTIONS`) and validation rules, and `public/index.html` is identical in both. If you change a question, update `server.py`, `lib/common.js`, both HTML copies, and the migration (if needed) together.
- `survey-vercel` has `RESULTS_PUBLIC = true` (`lib/common.js:16`), so the results and the CSV, which include personal data, are public. If you switch it to `false`, you must also remove the `/login → /results` redirect in `vercel.json`, otherwise you get an infinite redirect loop.
- The four HTML files at the root are fragments with no `<!doctype>`/`<head>`, written for the Claude artifact preview. Before deploying one, add the document wrapper the way `commute-break/index.html` does. `퇴근길쉼표.html` and `commute-break/index.html` have the same body, so a change to one should go into the other too.
- The PowerShell scripts in `survey-vercel/` and `comfort-letters/setup.ps1` are interactive: they prompt with `Read-Host`. The user has to run them in their own window.
- Never print or commit secret values: `survey/admin_password.txt`, `.env.local`, `supabase/.temp/pooler-url`.
