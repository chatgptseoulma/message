**종합 의견**
- 접근 통제, 인증, XSS, 인젝션, 비밀값 관리는 **양호**합니다.
- 주된 위험은 **누구나 무료로 계정을 무한히 만들 수 있다는 점을 이용한 악용**(신고로 남의 글 가리기, 스팸 방 뿌리기)입니다.
- 다음으로 **지웠는데도 남는 내용**(제목, 사이드바 미리보기, 신고 기록)이 문제입니다.
- 실제 피해가 나기 전에 **중 등급 4건을 우선 조치**할 것을 권장합니다.

## 3. 발견 사항 상세

> 판정: **확인됨** = 코드로 확인, **추정** = 가능성은 높으나 실제 재현은 안 함

### V-01 [중] 여러 계정으로 신고 자동 가리기 악용 — 확인됨
- **분류:** CWE-799 (상호작용 빈도 제어 미흡), CWE-840 (업무 로직 오류)
- **위치:** `api/reports.js:43-53`, `api/me.js:14-22`, `api/comforters.js:27-34`
- **시나리오:**
  - 공격자가 계정 3개를 미리 만들어 편들어 주기에 등록합니다. 둘 다 횟수 제한이나 심사가 없습니다.
  - 이후 올라오는 하소연 방이나 메시지를 세 계정으로 신고하면 자동으로 가려집니다(`moderated=true`).
  - 관리자 화면이 없어 잘못 가려져도 되돌리기 어렵습니다.
- **조치안:**
  - 신고 자격을 둡니다(예: 가입 후 일정 기간이 지났거나, 그 방에 글을 쓴 사람만).
  - 자동 가림을 "검토 대기"로 바꾸고 관리자가 되돌리는 경로를 만듭니다.
  - 계정 생성에 횟수 제한을 둡니다.

### V-02 [중] 계정·방 생성 남용 (스팸 뿌리기) — 확인됨
- **분류:** CWE-770 (자원 할당 제한 없음)
- **위치:** `lib/common.js:99-107` (`checkRate`), `api/rooms.js:74-76`, `api/me.js:14`
- **시나리오:**
  - 도배 제한(`checkRate`)이 계정 단위라, 계정을 여러 개 만들면 계정 수 × 분당 20개 방을 만들 수 있습니다. 각 방은 **모든 편들어 주는 사람에게 전송되고 알림**까지 뜹니다.
  - 동시에 요청을 보내면 한도를 넘길 수 있습니다(원자적 확인 아님).
  - 횟수 제한이 없는 기능: 가입, 닉네임 변경, 편들어 주기 등록, 공감, 신고, 차단, 방 설정, 회수.
- **조치안:**
  - 접속 주소(IP) 단위 제한을 둡니다.
  - 계정당 하루 방 개수 상한(예: 5개)을 둡니다.
  - 새 계정은 일정 시간 뒤부터 방을 만들게 합니다.
  - 한도 확인을 DB 함수로 원자 처리합니다.

### V-03 [중] 회수·가림·탈퇴 뒤에도 내용이 남음 — 확인됨
- **분류:** CWE-212 (민감 정보 불완전 삭제)
- **위치:** `api/message.js:17-22`, `api/reports.js:49-51`, `lib/rooms.js:99`, `20261105200000_broadcast_rooms.sql`
- **시나리오:**
  1. 첫 메시지를 회수해도 방 제목(`cb_threads.title`, 첫 메시지 앞 40자)은 그대로 남아 목록에 계속 보입니다.
  2. 신고로 가려진 메시지가 방의 마지막 메시지면, 왼쪽 목록 미리보기(`last_body`)에 원문이 계속 보입니다. 이 경우를 위한 문구 `MODERATED`가 정의만 되어 있고 쓰이지 않습니다.
  3. 편들어 주는 사람이 탈퇴하면 메시지는 지워지지만, 남의 방 미리보기(`last_body`)에는 그 사람 글이 남습니다.
- **조치안:**
  - 첫 메시지를 회수하면 제목도 "(회수된 메시지)"로 바꿉니다.
  - 마지막 메시지가 가려지면 미리보기를 `MODERATED` 문구로 바꿉니다.
  - 탈퇴할 때 그 사람이 마지막으로 쓴 방들의 미리보기를 다시 계산합니다.

### V-04 [중/하] 신고 증거 소실 — 확인됨
- **분류:** CWE-778 (감사 기록 불충분)
- **위치:** `20261106000000_safety_and_prefs.sql` (`cb_reports.target_user_id`, `message_id` 연쇄 삭제), `api/message.js:17`
- **시나리오:**
  - 신고당한 사람이 메시지를 회수하면 본문이 비워집니다.
  - 탈퇴하면 신고 기록 자체가 지워집니다. 관리자가 무엇이 문제였는지 확인할 수 없습니다.
- **조치안:**
  - 신고할 때 메시지 본문 사본을 신고 기록에 함께 저장합니다.
  - 대상자가 탈퇴해도 신고 기록은 남도록 연쇄 삭제를 "비우기(set null)"로 바꿉니다. 이는 DB 변경이지만 기존 데이터는 그대로 둡니다.

### V-05 [하] 익명성 약화·정보 노출 — 확인됨
- **분류:** CWE-359 (개인정보 노출)
- **위치:** `api/room.js:31-35`, `:65`, `api/rooms.js:48`, `api/comforters.js:6-25`
- **내용:**
  - "읽은 사람" 목록에, 글은 안 쓰고 방을 열어 보기만 한 사람의 닉네임까지 방 참여자 모두에게 보입니다.
  - 사용자 고유 id(`seeker_id`, `author_id`)가 응답에 포함되어, 닉네임을 바꿔도 같은 사람의 방들을 이어 볼 수 있습니다.
  - 편들어 주는 사람 목록(`GET /api/comforters`)은 로그인 없이 id·닉네임·소개를 돌려줍니다.
- **조치안:**
  - 읽은 사람 목록은 메시지 작성자 본인에게만 보여 주거나, 숫자만 보여 줍니다.
  - 방마다 다른 가명 id를 씁니다.
  - 편들어 주는 사람 목록은 로그인을 요구하고 인원 수만 돌려줍니다.

### V-06 [하] 이 기기에 여러 계정 열쇠가 원문으로 저장 — 확인됨
- **분류:** CWE-922 (민감 정보의 안전하지 않은 저장)
- **위치:** `public/index.html` (`comfort-letters-accounts`), `public/start.html:136`
- **시나리오:**
  - 공용 PC나 악성 브라우저 확장이 있으면, 또는 XSS가 하나라도 생기면 그 브라우저의 모든 계정이 탈취됩니다.
  - 비밀번호가 없고 열쇠를 바꿀(재발급) 방법도 없습니다.
- **조치안:**
  - 시작 화면에 "공용 PC에서는 쓰지 마세요" 안내를 넣습니다.
  - 열쇠 재발급 기능을 만듭니다.
  - CSP를 추가합니다(V-08).

### V-07 [하] 신고 이유 검사 우회 → 500 오류 — 확인됨
- **분류:** CWE-20 (입력 검증 부적절)
- **위치:** `api/reports.js:15` (`b.reason in REASONS`)
- **시나리오:** `reason`에 `"toString"`, `"constructor"`를 넣으면 검사를 통과한 뒤 DB 제약에 걸려 500 오류가 납니다. 데이터 피해는 없습니다.
- **조치안:** `Object.hasOwn(REASONS, b.reason)`으로 바꿉니다.

### V-08 [하] 보안 헤더 부족 (CSP, Permissions-Policy) — 확인됨
- **분류:** CWE-693 (보호 메커니즘 실패)
- **위치:** `vercel.json`
- **영향:** 지금은 XSS가 없지만, 나중에 생기면 피해를 줄일 마지막 방어선이 없습니다.
- **조치안:**
  - 스크립트를 별도 파일로 분리한 뒤 다음 정책을 적용합니다: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src https://fonts.gstatic.com; connect-src 'self'; frame-ancestors 'none'`
  - `Permissions-Policy: camera=(), microphone=(), geolocation=()`를 추가합니다.

### V-09 [하] 차단·가림 뒤 내 메시지 회수 불가 — 확인됨
- **위치:** `api/message.js:14`
- **시나리오:** 회수할 때도 방을 볼 수 있어야 해서, 방 주인에게 차단당했거나 방이 가려지면 내가 쓴 글을 지울 수 없습니다.
- **조치안:** 작성자 본인 확인만으로 회수를 허용합니다.

### V-10 [하] 이모지가 잘리면 깨진 글자 → 오류 가능 — 추정
- **분류:** CWE-176 (유니코드 처리 부적절)
- **위치:** `api/rooms.js:78` (`slice(0,40)`), `lib/rooms.js:72` (`slice(0,120)`)
- **시나리오:**
  - 40번째·120번째 글자 자리에 이모지가 걸리면 반쪽 글자가 저장되면서 오류가 날 수 있습니다.
  - 메시지는 저장된 뒤라, 다시 보내면 같은 메시지가 두 번 생길 수 있습니다.
- **조치안:** 글자 단위(`Array.from`)로 자릅니다.

### V-11 [하] 입력 검증 미흡 — 확인됨
- **분류:** CWE-20
- **내용:**
  - id 검사가 느슨해 특정 형식은 404 대신 500이 납니다.
  - `"12abc"` 같은 숫자 id를 12로 받아들입니다.
  - 글 대신 객체를 보내면 `"[object Object]"`로 저장됩니다.
  - 닉네임에 보이지 않는 문자(폭 없는 공백, 방향 바꾸기 문자)를 쓸 수 있고 같은 닉네임도 허용해서, 남을 흉내 내기 쉽습니다.
- **조치안:**
  - id를 엄격한 형식으로 검사합니다.
  - 숫자는 `^\d+$`만 받습니다.
  - 글은 문자열만 받습니다.
  - 닉네임에서 보이지 않는 서식 문자를 제거합니다.

### V-12 [하] 폴링 비용 증폭 — 확인됨
- **분류:** CWE-400 (자원 소모)
- **위치:** `api/room.js:16-35`
- **내용:**
  - 열린 방마다 3초마다 방 전체의 메시지 상태(최대 5000)와 반응(최대 5000)을 다시 읽고, 읽음 위치를 매번 저장합니다.
  - 메시지가 5000개를 넘으면 회수 반영이 빠집니다.
  - 사용자가 늘면 DB 사용량과 비용이 커집니다.
- **조치안:**
  - 바뀐 부분만 보냅니다.
  - 읽음 위치가 그대로면 저장을 건너뜁니다.

### 참고 (이미 알려진 사항)
- 탈퇴한 사용자 정보가 다른 서버 인스턴스에서 최대 60초 남습니다. 차단·권한 판단은 이 캐시를 쓰지 않아 권한에는 영향이 없습니다.
- 탈퇴하면 내 하소연 방과 그 안의 남의 답글까지 지워집니다. 의도된 동작이지만 안내 문구에 밝혀 두면 좋습니다.

## 4. 이상 없음으로 확인한 항목

| 영역 | 확인 내용 |
|---|---|
| 접근 통제 (IDOR) | 방 열람·쓰기·회수·공감·신고 모두 `loadRoom` → `canView`를 거침. 볼 수 없는 방은 404로 존재도 숨김. 신고 시 메시지가 그 방 소속인지 확인. 회수는 작성자만. 차단 해제·방 설정은 본인 행만. 방 닫기는 방 주인만. 계정 생성 이전 방은 DB 시각으로 차단. 예전 1:1 방은 당사자만. 차단은 양방향이고 캐시를 쓰지 않음 |
| 인증 | 열쇠는 192비트 난수, 서버는 SHA-256만 저장. 열쇠는 Authorization 헤더로만 받고 주소(URL)나 로그에 남지 않음 |
| CSRF / CORS | CORS 허용 헤더 없음 + Bearer 헤더 방식 → 다른 사이트에서 대신 요청 불가 |
| 인젝션 | 사용자 입력으로 DB 필터 문자열을 만드는 곳 없음. 조건 값은 검증됐거나 DB에서 온 값 |
| XSS | 모든 화면 출력이 textContent. 알림·대화상자·이모지 판·탭 제목도 평문. 링크에는 서버 id와 `tel:`만 |
| 클릭재킹 | `X-Frame-Options: DENY` |
| 오류 처리 | 500 오류는 일반 문구만, 상세는 서버 로그에만 |
| 비밀값 | 서비스 키는 Vercel 환경변수(민감)에만 있음. `.env.local`, `supabase/.temp/`는 배포·버전관리에서 제외. 스크립트는 비밀값을 로그에 쓰지 않음 |
| DB 권한 | 모든 `cb_*` 표에 RLS를 켜고 공개 키 권한을 회수함 → 서버를 거치지 않고는 접근 불가 |
| 입력 허용 목록 | 이모지·공감 반응은 정해진 목록과 정확히 일치해야 함. 요청 본문은 객체만 |
| 전송 구간 | HTTPS 강제(HSTS 2년, preload) |
