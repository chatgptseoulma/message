# CLAUDE.md — 퇴근길 빡침 우체통 LLM Wiki 스키마

이 폴더는 Andrej Karpathy의 "LLM Wiki" 패턴을 따르는 지식 베이스입니다.
- 원문: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f (2026-04-04)
- 사람은 자료를 넣고 질문합니다.
- LLM(Claude)은 위키를 쓰고 고치고 정리합니다.
- 위키는 Obsidian으로 열어 보기 좋게 만듭니다. 이 폴더를 그대로 vault로 열면 됩니다.

## 세 층

| 층 | 위치 | 규칙 |
|---|---|---|
| 원자료 | `raw/` | **고치지 않습니다.** 새 자료는 `YYYY-MM-DD_제목.md`로 추가만 합니다. 이미지는 `raw/assets/`에 둡니다. |
| 위키 | `wiki/` | LLM이 전부 관리합니다. 사람이 직접 고쳤다면 다음 작업 때 그 내용을 존중합니다. |
| 스키마 | 이 파일 | 사람과 LLM이 함께 고쳐 나갑니다. |

**읽기 전용 참고 자료**
- 앱 소스 `../comfort-letters/`와 `../docs/comfort-letters.md`는 원자료처럼 읽기만 합니다.
- 소스에서 확인한 사실은 페이지의 `sources`에 `code:<파일 경로>`로 적습니다.

## 위키 구조

```
wiki/
  index.md      모든 페이지 목록 (분류별, 링크 + 한 줄 요약)
  log.md        작업 기록 (추가만, 시간순)
  overview.md   전체 그림
  entities/     실제로 있는 것: 앱, 역할, 화면, 방, 열쇠, API, DB, 저장소
  concepts/     규칙·동작·정책: 볼 권한, 신고, 회수, 제한값, 배포 등
  sources/      원자료마다 요약 1쪽 (src-로 시작)
  analyses/     질문에 대한 답, 비교, FAQ, 이력 (질문에서 나온 좋은 답을 여기 보관)
```

## 페이지 규칙
- **파일 이름:** 한글 낱말을 `-`로 잇습니다 (예: `하소연-방.md`).
  - 폴더가 달라도 **이름이 겹치면 안 됩니다.** 위키 링크가 이름으로 찾기 때문입니다.
- **링크:** Obsidian 위키 링크를 씁니다. `[[하소연-방]]`, 보이는 글을 바꿀 때는 `[[하소연-방|하소연 방]]`.
  - 다른 페이지의 개념이 처음 나오면 링크를 겁니다.
- **머리 정보(frontmatter):** 모든 페이지에 붙입니다.
  ```yaml
  ---
  type: entity | concept | source | analysis | overview
  tags: [역할, 화면, 보안 …]
  sources: [src-프로젝트문서, code:public/index.html]
  updated: YYYY-MM-DD
  ---
  ```
- **본문 순서:** 한 줄 정의 → 핵심 사실(목록·표) → 관련 페이지.
  - 사실마다 근거가 `sources`에 있어야 합니다.
  - 추정은 "(추정)"으로 표시합니다.
- **자료가 서로 다를 때:** **더 새로운 자료를 따르고**, 옛 내용은 "바뀐 점"으로 남깁니다.
  - 예: 신고 3건 자동 가림 → 관리자 검토로 바뀜
- **개인정보:** 실제 사용자의 닉네임, 하소연, 메시지 내용은 넣지 않습니다. 숫자와 집계만 넣습니다.
- **글쓰기:** 한국어 평어 존댓말로 씁니다. 표와 목록을 우선하고, 짧은 문장으로 씁니다.

## 작업 흐름

### 넣기 (ingest)
1. `raw/`에 새 자료를 넣고 읽습니다. 핵심 내용을 사람과 짧게 확인합니다.
2. `sources/src-<제목>.md` 요약 페이지를 만듭니다.
3. 관련된 entity·concept 페이지를 고치거나 새로 만듭니다.
   - 한 자료가 10~15쪽에 영향을 줄 수 있습니다.
   - 충돌하는 내용은 위 규칙대로 처리합니다.
4. `index.md`를 고칩니다.
5. `log.md` 끝에 `## [YYYY-MM-DD] ingest | 제목`을 추가하고, 바뀐 페이지를 적습니다.

### 묻기 (query)
1. `index.md`를 먼저 읽고, 관련 페이지를 찾아 읽습니다.
2. 페이지를 인용하며 답합니다 (예: "[[방-볼-권한]]에 따르면…").
3. 다시 쓸 만한 답이면 `analyses/`에 페이지로 남기고 index를 고칩니다.
4. `log.md`에 `## [YYYY-MM-DD] query | 질문 요약`을 추가합니다.

### 점검 (lint)
1. 다음을 찾습니다.
   - 페이지끼리 모순되는 내용
   - 새 자료로 낡은 주장
   - 들어오는 링크가 없는 고아 페이지
   - 깨진 `[[링크]]`
   - 자주 나오는데 페이지가 없는 개념
   - 근거가 없는 사실
2. 고칠 수 있는 것은 고치고, 더 필요한 자료나 질문은 log에 제안으로 남깁니다.
3. `log.md`에 `## [YYYY-MM-DD] lint | 요약`을 추가합니다.

최근 기록 보기: `grep "^## \[" wiki/log.md | tail -5` (PowerShell: `Select-String '^## \[' wiki\log.md | Select-Object -Last 5`)
