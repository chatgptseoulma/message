# CLAUDE.md — 카카오톡 대화 LLM Wiki 스키마

이 폴더는 Andrej Karpathy의 "LLM Wiki" 패턴을 따르는 지식 베이스입니다.
- 원문: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f (2026-04-04)
- 사용자가 PC 카카오톡에서 내보낸 대화(.txt)를 원자료로 넣습니다.
- Claude가 위키를 쓰고 관리합니다.
- Obsidian에서 이 폴더를 vault로 열어 봅니다.

## 세 층

| 층 | 위치 | 규칙 |
|---|---|---|
| 원자료 | `raw/` | **고치지 않습니다.** 파일 이름은 `YYYY-MM-DD_방이름_원래이름.txt`로 붙입니다. 사람이 만든 요약도 원자료로 둡니다. 이미지는 `raw/assets/`에 둡니다. |
| 위키 | `wiki/` | LLM이 관리합니다. |
| 스키마 | 이 파일 | 사람과 LLM이 함께 고칩니다. |

원본 내보내기 파일은 `../카카오톡/`에 있습니다. 거기서 `raw/`로 복사해 옵니다.

## 위키 구조
```
wiki/
  index.md      모든 페이지 목록 (분류별)
  log.md        작업 기록 (추가만)
  overview.md   어떤 방이 있고 무엇을 얻을 수 있는지
  entities/     대화방, 도구·모델, 서비스
  concepts/     노하우 주제, 작업 방법, 방 규칙, 이야기 주제
  sources/      원자료마다 요약 1쪽 (src-로 시작)
  analyses/     질문 답, 비교표, 가이드, 링크 모음
```

## 페이지 규칙
- **파일 이름:** 한글 낱말을 `-`로 잇습니다. 폴더가 달라도 이름이 겹치면 안 됩니다.
- **링크:** `[[페이지]]` 또는 `[[페이지|보이는 글]]`
- **머리 정보:**
  ```yaml
  ---
  type: entity | concept | source | analysis | overview
  tags: [...]
  rooms: [AI영상방, 아침인사방]
  sources: [src-AI영상방-대화 L1234-1290]
  updated: YYYY-MM-DD
  ---
  ```
- **근거:** 원문 줄 번호로 적습니다 (예: `L1234`). 줄 번호는 `raw/`에 복사한 txt 파일 기준입니다.
- **자료가 서로 다를 때:** 원문 대화 > 사람이 만든 요약 순으로 믿습니다. 시간이 다르면 더 새로운 말을 따릅니다.
  - 도구 가격·한도·모델 버전은 자주 바뀝니다. "○월 ○일 대화 기준"이라고 적습니다.

## 넣지 않는 것 (개인정보·안전)
- 전화번호, 이메일, 실명, 주소, 계좌. 오픈채팅 닉네임은 써도 되지만, 닉네임에 붙은 지역은 쓰지 않습니다.
- AI 안전장치·검열을 우회하는 방법
- 여러 계정으로 약관을 어기며 할인이나 무료를 반복해서 받는 방법
- 선정적인 내용, 다툼에서 누구를 탓하는 서술 (사건은 중립적으로만 씁니다)
- 남의 글 전문. 인용은 짧게 하고 요약합니다.
- 노하우는 **방 안 의견**이며 검증하지 않았다는 점을 밝힙니다.

## 작업 흐름

### 넣기 (ingest)
1. 새 내보내기 파일을 `raw/`에 복사합니다.
2. 날짜 구분선(`--------------- YYYY년 …`)으로 기간을 나눠 읽습니다. 길면 기간별로 나눠 병렬로 읽습니다.
3. `sources/src-…` 요약 페이지를 만듭니다. 기간, 메시지 수, 많이 말한 사람, 화제를 적습니다.
4. 도구, 노하우, 규칙 페이지를 만들거나 고칩니다.
5. `index.md`를 고치고, `log.md`에 `## [YYYY-MM-DD] ingest | 제목`을 추가합니다.

### 묻기 (query)
1. index를 읽고 관련 페이지를 찾아 읽습니다. 필요하면 원문 줄을 확인합니다.
2. 페이지를 인용해 답합니다. 좋은 답은 `analyses/`에 남깁니다.
3. `log.md`에 `## [YYYY-MM-DD] query | 질문`을 추가합니다.

### 점검 (lint)
1. 다음을 찾습니다.
   - 깨진 링크와 고아 페이지
   - 모순
   - 낡은 가격·버전 정보
   - 근거 줄 번호가 없는 사실
   - 페이지가 없는 자주 나오는 도구
2. 고칠 것은 고치고, 나머지는 log에 제안으로 남깁니다.
3. `log.md`에 `## [YYYY-MM-DD] lint | 요약`을 추가합니다.
